# Guardrails (read first)

These constraints come from how the experiment runs, not from style preferences.

## Never touch
- `.env` - untracked, machine-specific runtime state (real endpoint, prompt,
  credentials). Read `.env.example` for the parameter schema and ask the user for
  values instead of opening `.env`. Never add it to git.
- `local-repo/` - the tracked offline Maven repository. Every build resolves from it;
  deleting or pruning it breaks the build on the cluster.
- `local-repo -DskipTests/` - 1,146 files accidentally committed by a mis-quoted Maven
  invocation. Nothing references it. Report it; remove it only when the user asks.

## Never run without explicit approval
Every execution occupies the LLM endpoint (or a dedicated SLURM node) for
`USER_RAMP_MINUTES + SIMULATION_MINUTES` plus 10-15 minutes of overhead. So:
- do not call `gatling:test`, `run-llm-workload.sh`, `run_queue.py start` or `sbatch`
  on your own initiative;
- safe substitutes: `python run_queue.py run <name> --dry-run`,
  `python run_queue.py list`, `python estimate_requests.py`, and `... test-compile`.

## Never change silently
- `-o` and `-Dmaven.repo.local=...` in Maven commands (there is no network at build
  time). A resolution failure is a finding to report, not a reason to go online.
- `dependency-reduced-pom.xml` - generated by the shade plugin; `pom.xml` is the build
  file, as the README states.
- The fixed seed (`new Random(42)`) and the order in which schedules are generated:
  run-to-run comparability is the entire point of this tool.
- The meaning of existing `.env` keys - add keys, do not redefine them.
- The queue's strict FIFO, sequential design. Do **not** convert it to a SLURM job
  array (README section 4.2 explains why).
- Do not add a dependency or plugin version that is absent from `local-repo/`.
- `.clineignore` patterns. Keep exactly one pattern per line and put any explanation on
  the line above: gitignore syntax (used by Cline and by the guard hook) has no inline
  comments, so `pattern   # note` silently matches nothing.

## Never commit
`queue/`, `results/`, `logs/`, `target/`, `.env`, `*.out`, `*.err`.

## Personal data
`setup_tunnels.ps1` and `setup_tunnels.bat` embed a real `user@host`. Do not copy that
into `README.md`, `AGENTS.md`, `.env.example` or any new example.

## Not project documentation
`.github/copilot-instructions.md` was a scaffolding checklist and has been replaced by
`AGENTS.md`. Do not treat it as a specification if it reappears.
